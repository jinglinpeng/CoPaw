Pcurrent / P4.1 源码快照

P4.1 = P4 + 隐私闸门的两处修复。Pcurrent.json 指向 P4.1。
P4 及其冻结记录保持原字节；P4 的提交 9e301810f8a4dddd7d17abc7783776aceb4a287d 仍在本分支历史中。
P4.1 尚未在任何 benchmark 上实测。顾问系统提示正文与 P3、P4 相同。

修复来源：用 P4 中间件重建 P3 的 15 次 DAB 咨询请求并离线回放，
隐私开的请求中有 4 次共 29 个查询结果 ID 没有遮盖。原因有两个：
1. worker 在代码或提问里写出结果 ID 的一段（如过滤用的 ID 尾部 NIliIAG），
   这段被当成 worker 自己的话而公开。现在结果 ID 的 5 个字符以上前缀和后缀，
   由 worker 写出时仍算数据。
2. 以 ID 为键的字典（如 {"ka0Wt000000Eo6cIAC": ...}）被当成字段名公开。
   现在同时含数字和大写字母的键算数据，application_number、rowCount 这类
   字段名不受影响。
修复后同一回放中剩余 3 个命中，均为 worker 在代码里自己起的变量名，不是数据。
只有这 4 次请求的占位符数量变化（总数 714 → 752），其余 11 次请求不变。

隐私开关、其他遮盖规则、失败识别和中间件均与 P4 相同；隐私关时发给顾问的内容与 P4 一致。
暂不处理：遮盖后的数字不带量级。回放中 Max 在 PATENTS.query1 因关键计数
（244 个重复申请）被遮而选错口径。小写单词形式的字典键（如以类别值为键）
仍按字段名处理。

推荐实验组：P4.1 隐私关（= P3 + 失败识别）与 P4.1 隐私开。
验证命令、回放与顾问对比结果见 P4.1-validation.json。
使用本版本运行实验时，记录具体 Git 提交、P4.1.json 中的源码哈希及隐私开关取值。
