# Snapshot UI 评审回复

> 针对 `docs/v2/reviewer-ui.md` 中每条意见的逐一回复。
> 日期: 2026-04-08

---

## 总体评价

这份评审非常专业，切中了多个实际的功能闭环和可扩展性问题。P0 中大部分意见直接采纳并已更新到原型中。少数意见做了调整（主要是在 V1 范围内做适当简化），以下逐条说明。

---

## P0 逐条回复

### 1. 加密导出/导入链路不完整

**结论：采纳，已更新原型。**

完全同意。加密功能如果只有一个 checkbox 却无法输入密码，等于废功能。

已做的改动：
- **导出 Modal**：勾选「使用密码加密」后展开密码输入框和确认密码输入框，显示提示"密码不会被保存，丢失后无法恢复快照"。
- **导出 Modal**：勾选「包含密钥信息」后展开「输入 YES 确认」输入框，未正确输入时下载按钮置灰。包含密钥时自动勾选加密选项。
- **导入流程**：步骤从 3 步扩展为 4 步（上传 → 解密 → 验证 → 结果）。新增「解密」步骤页面，检测到加密包后要求输入密码才能继续。
- 关于"包含密钥时强制要求设置密码"：**采纳**，已在 UI 中体现为自动勾选加密并显示提示。

### 2. 恢复选择"克隆为新 Agent"后缺少目标信息输入

**结论：采纳，已更新原型。**

确实是功能闭环缺失。

已做的改动：
- 选择「克隆为新 Agent」后展开目标 Agent ID 输入框。
- 提供默认命名预设（如 `default-clone-1`），显示在 placeholder 中。
- 添加即时重名校验提示。
- **多 Agent 快照的克隆**：采纳建议，但 V1 简化处理——多 Agent 快照的恢复固定为「选择其中一个 Agent 恢复」，不支持批量克隆。理由：批量克隆的 ID 映射 UI 复杂度过高，且真实使用频率极低。在恢复 Modal 中增加 Agent 选择下拉框。

### 3. 多 Agent 展示方式不可扩展

**结论：采纳，已更新原型。**

正确的可扩展性问题。虽然 CoPaw 目前的典型 Agent 数量是 3-10 个，但设计上应该留有余地。

已做的改动：
- **列表页「包含 Agent」列**：最多显示 2 个 chip，超出部分显示 `+N` 徽章。鼠标悬停 `+N` 时 Tooltip 显示完整列表。
- **恢复弹窗**：改为摘要格式「共 N 个 Agent」+ 折叠展开完整列表。
- **全量快照**：直接显示紫色标签「全部 Agent（N 个）」，不再逐个列出。

### 4. 创建快照的"指定 Agent"选择器不支持真实规模

**结论：部分采纳。**

- **搜索功能**：采纳。在多选面板顶部增加搜索输入框。
- **已选 N 个摘要**：采纳。固定显示在选择器底部。
- **Transfer 组件**：**V1 不采纳**。理由：Transfer 的左右面板模式对于 CoPaw 这种个人 Agent 工作站来说交互过重。V1 的目标用户通常有 3-20 个 Agent，带搜索的 checkbox 列表完全够用。如果后续用户量和 Agent 规模增长到需要虚拟滚动的程度，再迭代为 Transfer 组件。
- **按标签/状态筛选**：V1 不做。CoPaw 的 Agent 目前没有标签和分组功能，筛选维度不足。

### 5. 多 Agent 导入时 ID 映射语义不清

**结论：采纳，已更新原型。**

这个问题确实存在。一个输入框无法覆盖多 Agent 场景。

已做的改动：
- **单 Agent 包**：保留单个「导入为 Agent ID」输入框。
- **多 Agent 包**：上传文件后，解析 manifest 显示映射表（原 Agent ID → 导入后 Agent ID），每行可单独修改。对冲突项自动添加 `-imported` 后缀并高亮提示。
- 由于导入时需要先上传文件才能知道是单 Agent 还是多 Agent，所以映射表出现在上传完成、解析 manifest 之后（即步骤 2「验证」阶段展示）。

### 6. 系统级功能与"当前 Agent"上下文冲突

**结论：采纳，已更新原型。**

同意这个语义冲突问题。快照列表是全局的，不应暗示与当前 Agent 有关。

已做的改动：
- 快照列表页的 Agent 选择器添加淡化样式（降低透明度）。
- 页面标题下方增加副标题："管理所有 Agent 的快照。与当前选中的 Agent 无关。"
- 创建快照 Modal 中已通过「快照范围」三选项明确了范围，不依赖侧边栏选择器的暗示。

### 7. 导入结果页状态定义冲突

**结论：采纳，已更新原型。**

这是一个 bug。页面顶部显示 `needs_review`（黄色），阶段 2 内部又显示 `needs_setup`（红色），两个状态矛盾。

修正规则：
- **一个导入结果只有一个主状态**，取最严重的那个。
- 如果存在「必须」项未完成 → `needs_setup`（红色）
- 如果只有「建议」项 → `needs_review`（黄色）
- 页面顶部、阶段 2 内部、侧边栏全部统一为同一状态。
- 原型中已修正为统一的 `needs_setup`。

关于"聊天测试"按钮：
- **部分采纳**。当状态为 `needs_setup` 时，改为置灰 + 提示"完成必须项后可用"，而非完全隐藏。理由：`needs_setup` 在某些情况下 Agent 仍可对话（如缺少的是渠道认证而非 LLM API Key），完全隐藏可能让用户误以为 Agent 完全不可用。但默认不建议此时测试，所以置灰。

### 8. 高风险操作缺少硬性护栏

**结论：采纳，已更新原型。**

同意。纯文案提示不够，需要交互层面的硬约束。

已做的改动：
- **恢复操作**：主按钮默认置灰，需勾选「我理解此操作将覆盖当前工作空间」后激活。
- **含密钥导出**：勾选后展开 YES 确认输入框，未输入正确值时下载按钮置灰。
- **删除操作**：从图标按钮改为「更多操作」下拉菜单中的文本项「删除快照」，点击后弹二次确认 Popconfirm。
- **批量删除**：选中多条后「清理旧快照」按钮旁出现「删除选中（N）」，需二次确认。

## P1 逐条回复

### 9. 恢复确认页对影响范围表达不够清楚

**结论：采纳，已更新原型。**

已做的改动：
- 增加「本次恢复将影响」清单，列出将被替换的具体内容（配置、会话、技能、定时任务等）。
- 多 Agent 快照时列出受影响的 Agent 列表。
- 明示自动备份策略："系统将自动创建当前状态的备份（命名格式：`{agent_id}.backup.{timestamp}`），恢复失败时可回滚。"

### 10. 创建快照弹窗信息结构偏重

**结论：采纳，已更新原型。**

已做的改动：
- 多选面板**默认隐藏**，仅在选择「指定 Agent」时展开（通过 JavaScript 控制 display）。
- 「排除内容」区域改为折叠式，默认收起，点击「高级选项」展开。
- 预估大小始终显示在底部固定位置，随用户选择实时更新。

### 11. 快照列表页缺少管理能力

**结论：部分采纳。**

- **搜索/筛选栏**：采纳。在表格上方增加搜索框 + Agent 下拉筛选 + 内容类型筛选。
- **排序**：采纳。表头「创建时间」「大小」支持点击排序。
- **详情抽屉**：**V1 不做**。理由：表格中已展示了主要信息（备注、Agent、时间、大小、内容标签），manifest 详情属于开发者调试信息，V1 优先级不高。P2 再增加详情 Drawer。
- **删除改进**：采纳。从垃圾桶图标改为「更多操作」下拉菜单，提供「删除」和「查看详情」（P2）。

### 12. 失败态和异常态不完整

**结论：部分采纳。**

V1 原型中补充以下关键失败态页面：
- **导入失败**：通用错误页面（涵盖包损坏/校验失败、版本不兼容、资源超限），显示错误类型、详细信息和建议操作。
- **解密失败**：密码错误或文件被篡改的提示，允许重新输入密码。

以下失败态在 V1 中通过 **通用错误组件** 覆盖，不单独设计专属页面：
- 磁盘空间不足：在验证阶段检测并在进度页面显示错误。
- 恢复中断：由后端三阶段状态机处理，UI 显示恢复进度和自动回滚提示。

## P2 回复

### 14. 自动备份和来源管理

**同意延后。** V1 中"自动备份"仅在恢复时由系统自动创建，不暴露给用户管理。来源区分（手动/自动/导入）在 V1 中通过内容标签间接体现。P2 增加正式的来源字段和保留策略。

### 15. Agent 状态页与待办清单联动

**同意延后。** V1 的待办清单已提供「前往 →」按钮跳转到对应页面。P2 可以做更深度的集成，比如在状态页内嵌待办清单、完成后自动刷新状态等。
