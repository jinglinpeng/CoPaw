# Snapshot UI 评审（开发对接版）

## 说明

以下问题基于 `docs/v2/snapshot-design-v2.md`、`docs/v2/ui-design.md`、`docs/v2/snapshot-ui-prototype.html` 和当前 Console 页面观察整理，目标是给开发和设计一个可直接执行的修正清单。

建议按 `P0 -> P1 -> P2` 顺序处理。`P0` 是首版落地前必须解决的问题，否则会出现功能闭环断裂、用户无法完成操作或明显误导。

---

## P0 必须修正

### 1. 加密导出/导入链路不完整

问题：

- 导出页有“使用密码加密”选项，但没有密码输入框、确认密码、密码规则、忘记密码提示。
- 导入页没有“检测到加密包后输入密码”的步骤。

影响：

- 用户不知道密码在哪里输入。
- 加密导出和加密导入无法形成完整闭环。

建议：

- 勾选加密后展开 `密码`、`确认密码` 两个字段。
- 显示“密码不会被保存，丢失后无法恢复”。
- 若导出包包含密钥，强制要求设置密码。
- 导入时若检测到加密包，进入单独的密码输入步骤，不应直接进入上传完成/校验流程。

### 2. 恢复选择“克隆为新 Agent”后缺少目标信息输入

问题：

- 恢复弹窗提供“克隆为新 Agent”模式，但没有目标 Agent 名称/ID 输入框，也没有冲突处理。

影响：

- 用户不知道新 Agent 会叫什么。
- 无法预判重名时如何处理。
- 多 Agent 快照场景下完全不清楚是全部克隆还是部分克隆。

建议：

- 选择“克隆为新 Agent”后展开目标 Agent ID 输入框。
- 提供默认命名预设。
- 增加重名即时校验。
- 多 Agent 快照需要明确“全部克隆”或“按映射克隆”，并提供对应 UI。

### 3. 多 Agent 展示方式不可扩展

问题：

- 原型大量使用 chip/tag 平铺展示 Agent。
- 列表页“包含 Agent”、恢复弹窗“包含 Agent”、创建快照“指定 Agent”都存在同类问题。

影响：

- 几十到几百个 Agent 时页面会被撑爆。
- 用户无法快速确认操作范围。

建议：

- 列表页仅显示前 2 到 3 个 Agent，加 `+N` 汇总。
- 点击后通过 Drawer/Popover 展示完整列表和总数。
- 恢复弹窗改为“共 N 个 Agent”的摘要卡片，而不是直接铺标签。

### 4. 创建快照的“指定 Agent”选择器不支持真实规模

问题：

- 当前是 checkbox 堆叠。
- 不支持搜索、筛选、批量操作。

影响：

- Agent 稍多就无法使用。
- 选择效率和准确性都很差。

建议：

- 改成带搜索的多选组件或 Transfer 组件。
- 支持按名称、前缀、标签、状态筛选。
- 显示固定的“已选 N 个”摘要区。
- 大规模数据场景下预留虚拟滚动。

### 5. 多 Agent 导入时 ID 映射语义不清

问题：

- 导入页只有一个“导入为 Agent ID”输入框。
- 多 Agent 包场景下，不清楚这个字段到底作用于谁。

影响：

- 用户无法理解导入后的命名结果。
- 重名处理逻辑不透明。

建议：

- 单 Agent 包时保留单个目标 ID 输入框。
- 多 Agent 包时改为映射表：`原 Agent ID -> 导入后 Agent ID`。
- 对冲突项提供自动重命名建议，并允许逐项修改。

### 6. 系统级功能与“当前 Agent”上下文冲突

问题：

- Snapshot 放在 `Settings` 下是对的，但页面仍保留很强的“当前 Agent”上下文。
- 列表页又展示系统范围快照，语义不一致。

影响：

- 用户会误以为列表被当前 Agent 过滤。
- 用户会误以为“创建快照”默认只针对当前 Agent。

建议：

- 进入 Snapshot 后弱化或隐藏当前 Agent 选择器。
- 如果保留，必须明确说明“仅用于创建默认范围，不影响列表”。
- 页面顶部增加“系统级快照中心”的说明。

### 7. 导入结果页状态定义冲突

问题：

- 结果页顶部是 `needs_review`，阶段 2 又显示 `needs_setup`。
- 同页还有“打开聊天测试”按钮。

影响：

- 用户无法判断 Agent 当前是否可用。
- 在必须项未完成时过早提供聊天入口，会制造错误预期。

建议：

- 一个导入结果只能有一个主状态。
- 顶部状态、侧栏状态、Agent 管理状态共用同一套规则。
- 存在必须项未完成时，不显示“打开聊天测试”。
- 增加汇总文案，例如“还需完成 2 个必须项后才能正常运行”。

### 8. 高风险操作缺少硬性护栏

问题：

- 恢复、含密钥导出、删除等操作目前主要依赖提示文案。
- 页面缺少输入确认、必填校验、主按钮禁用规则。

影响：

- 容易误触。
- 用户不知道当前是否满足执行条件。

建议：

- 危险操作增加明确的二次确认。
- 含密钥导出必须走强约束流程，不应只是普通 checkbox。
- 主按钮与必填项绑定，缺项时置灰并显示原因。

---

## P1 建议首版一起做

### 9. 恢复确认页对影响范围表达不够清楚

问题：

- 只强调“替换当前工作空间”，但对多 Agent、全局配置、密钥的影响范围说明不足。

建议：

- 增加“本次恢复将影响”清单。
- 单独高亮全局配置影响。
- 明示自动备份的命名、保留和失败回退策略。

### 10. 创建快照弹窗信息结构偏重

问题：

- 多选面板默认展开。
- “包含内容”和“排除内容”同时出现，认知负担较高。
- 弹窗较长，重点层次不清。

建议：

- 默认只展示最常用路径。
- 只有选“指定 Agent”后才展开选择器。
- 将内容选择拆成“默认包含”和“可选排除”。
- 用动态大小预估反馈用户选择结果。

### 11. 快照列表页缺少管理能力

问题：

- 目前更像演示表格，不适合长期使用。
- 缺少搜索、过滤、排序、来源区分、详情查看。

建议：

- 增加按 Agent、时间、大小、是否含密钥的筛选和排序。
- 增加详情抽屉查看 manifest、兼容性、来源、内容摘要。
- 删除不要只用垃圾桶图标，至少提供清晰文本或二级菜单。

### 12. 失败态和异常态不完整

问题：

- 原型只覆盖了主要成功流，失败流设计不足。

建议补齐：

- 导入包损坏/校验失败
- 密码错误或文件被篡改
- 版本不兼容
- 磁盘空间不足
- 恢复中断后的继续/回滚
- 资源超限


## P2 后续迭代

### 14. 自动备份和来源管理

建议：

- 区分“手动创建”“自动备份”“导入生成”。
- 支持更清晰的来源、保留策略和清理策略展示。

### 15. Agent 状态页与待办清单联动

建议：

- 进一步打通状态页、待办项、修复入口之间的跳转闭环。
- 用户应能从状态直接进入具体修复动作，而不是只看到状态标签。

---

## 建议保留

- Snapshot 放在 `Settings` 分组，这个信息架构方向是对的。
- 导入后的“两阶段反馈 + 待办清单”方向是对的。
- 导出默认剥离 secrets、导入默认静默态，这两个安全原则建议保留。

---

## 结论

当前原型已经把主要页面画出来了，但还没有达到可直接开发的程度。最需要先修的是 `功能闭环`、`多 Agent 扩展性`、`状态一致性` 和 `高风险操作护栏`。建议先把 P0 项目补齐，再进入实现和细节打磨。
